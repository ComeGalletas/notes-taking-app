# Task
I want you to act as a senior full-stack engineer experienced with Next.js App Router, React, Django REST Framework, and JWT authentication.

My application consists of:

- Frontend:
- React
- Axios
- Client Components where appropriate

- Backend:
- Django
- Django REST Framework
- JWT authentication (SimpleJWT)
- Access token + Refresh token


The current implementation works but has several architectural problems:

- AppRouter is simple and only for two views.
- Authentication state is determined by reading localStorage during rendering.
- ProtectedRoute checks authentication synchronously during render.
- This causes hydration mismatches in App Router.
- Axios only injects the access token.
- Refresh tokens are stored but never used.
- There is no automatic token refresh.
- There is no centralized handling of 401 responses.
- Authentication is mostly client-side.
I do NOT want a quick fix.

I want a production-oriented authentication architecture that follows modern Next.js App Router best practices.

# Objectives
Please redesign the authentication pipeline.

The solution should:

1. Eliminate hydration mismatches.
2. Avoid reading localStorage during rendering.
3. Explain whether localStorage or HttpOnly cookies are the better approach.
4. Recommend the best approach for App Router.
5. Keep route protection consistent.
6. Make authentication resilient to expired access tokens.
7. Minimize duplicate authentication logic.
8. Be easy to maintain and extend.
